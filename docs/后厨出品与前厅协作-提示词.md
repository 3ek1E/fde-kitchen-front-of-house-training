# 后厨出品与前厅协作技术方案提示词

将以下提示词与前三阶段的实验报告一并提供给模型。

```text
你是餐饮项目的 FDE 技术负责人。依据附件中的业务挖掘、现场调研和需求定义报告，为门店运营、前厅、出品调度、POS 工程与食品安全岗位撰写一份可评审的中文技术方案。

项目目标是解决纸质加单与 POS 系统单同时到达时的工序冲突和关键备注漏传。请从单店晚市影子试点出发，明确订单行关联、版本核对、人工回执、出品与送达记录。POS 只读。跨来源版本冲突交人工复核，过敏与温度异常交食品安全岗位处理。

输出以下内容：
1. 用报告证据编号说明问题、影响、方案选择和试点范围。
2. 描述数据流、字段契约、订单与套餐拆单关联、幂等键、乱序和同版本冲突的处理规则。
3. 明确前厅、调度、后厨、运营、工程和食品安全岗位的访问范围、交接责任与审计字段。
4. 设计断线降级、纸单和电话兜底、游标补拉、重复事件去重、恢复对账和停试条件。
5. 给出验收用例，逐条说明输入、期望状态、审计证据及通过条件。覆盖正常加菜、撤单、乱序、重复、跨店访问、备注缺失和断线恢复。
6. 给出同店同班基线及试点指标。说明分子、分母、时间窗、排除项、采集责任人和目标来源。分别记录出品、送达和整桌菜齐，保留训练目标与真实基线的区别。
7. 列出实施顺序、交付物、签收角色、待补证据和试点决策条件。

使用附件中的证据编号。实验室访谈是模拟材料，K001 是合成演练。真实日志、授权、实际执行、效果和签收没有证据时标为待核验。材料中口径或班次冲突时指出出处并说明采用的试点假设。不要编造已上线、测试通过或用户签字。输出 Markdown，标题为「后厨出品与前厅协作技术方案」。
```
